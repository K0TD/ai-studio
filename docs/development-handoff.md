# Отчет для продолжения разработки

Дата: 22 октября 2026 года. Отчет описывает завершенную работу в этой сессии; это не подтверждение развертывания на боевом сервере.

Инструкция запуска и обслуживания: [production.md](./production.md). Настройки: [пример для Docker](../.env.docker.example), [пример для локального запуска](../apps/demo/.env.example).

## Принятые решения

- Целевое окружение — VPS с Docker Compose, PostgreSQL, отдельным worker и Caddy для HTTPS.
- Публичная регистрация закрыта. Пользователей создает администратор; пароль задается по одноразовой ссылке, действующей 24 часа. Почтовая интеграция для этого не нужна.
- Основной администратор входит через `/admin/login` по `ADMIN_LOGIN` и `ADMIN_PASSWORD` из окружения. Учетная запись синхронизируется при запуске Docker web; изменение реквизитов отзывает ее сессии. Без Docker предусмотрена команда `sync-admin`.
- Роли: `user`, `vip`, `admin`. Роль VIP и административная роль не дают бесплатных генераций и не обходят индивидуальные права на генерацию.
- Администратор явно назначает разделы, модели, суточный бюджет и максимум одновременных заданий. Начальный баланс — ноль, разрешения закрыты.
- Перед запуском сервер рассчитывает оценку и максимум списания. По умолчанию максимум — оценка плюс 20%; расчет действует пять минут.
- При наличии стоимости провайдера списывается факт в пределах максимума. Превышение учитывается как расход сервиса. Если стоимость отсутствует, списывается согласованная оценка с отметкой `estimated`. Фактический ноль остается нулем.
- Неподтвержденные модели и режимы отключены. Успешных моков, фиктивной музыки и подстановки демонстрационных результатов в рабочем API нет.

## Что реализовано

### Авторизация и администрирование

- Better Auth с username-входом администратора, email-входом пользователей и серверной проверкой сессии и актуальной строки пользователя в БД.
- Защита административных страниц и API; предварительные перенаправления через Next.js `proxy.ts`.
- Ограниченный набор публичных методов Better Auth, запрет изменения реквизитов основного администратора через пользовательские методы.
- Создание аккаунта и перевыпуск приглашения, роли, одобрение, блокировка, индивидуальные разрешения, пополнение и отзыв доступного баланса.
- Журнал финансовых операций и административных изменений; ограничения БД запрещают переписывать эти журналы.
- CSRF-проверка Origin, ограничение частоты запросов в PostgreSQL, ограничение размеров запросов и проверка входных данных через Zod.

### Деньги, генерация и результаты

- Денежные остатки и резерв в PostgreSQL; арифметика в целых копейках, суммы API передаются десятичными строками.
- Атомарное резервирование под блокировкой пользователя, проверка прав, баланса, суточного бюджета и параллельных заданий.
- Идемпотентные запуски и завершения. Повторный запрос не создает повторное списание.
- Очередь в PostgreSQL с lease, heartbeat и обработкой отдельным worker. Обработка не зависит от браузера.
- Неопределенный результат платной отправки переводится в `reconciling`, без автоматической повторной отправки и возврата резерва; предусмотрена административная сверка.
- Закрытые файлы и результаты с проверкой владельца, поддержкой Range и ограничением загрузок. Медиа хранятся вне `public`.
- Серверный каталог и проверка возможностей моделей. Для поддерживаемых TTS предусмотрена оценка по явно опубликованному тарифу за символы; модели без подтвержденной формулы цены блокируются.
- Старый гостевой `/api/studio/*` отключен. Алиасы `/api/syntx/*` используют защищенные обработчики основного API.
- Баланс, история, чаты и разрешения загружаются с сервера. Браузер больше не начисляет, не списывает и не возвращает деньги.

### Развертывание

- Dockerfile, Compose, Caddy, проверки состояния, отдельный запуск миграций и синхронизации администратора.
- Env-файлы и операционные секреты исключены из Git и Docker build context; примеры настроек остаются в репозитории.
- Скрипты зашифрованного внешнего резервирования через restic и восстановления в пустое окружение.
- CI для типов, lint, тестов, сборки, аудита зависимостей и сканирования секретов.

## Фактически выполненные проверки

- Финальный общий `bun test`: **78 passed, 0 failed**, 14 файлов, 217 проверок. Интеграционные сценарии выполнялись на отдельной PostgreSQL с примененными миграциями; платные запросы RouterAI не отправлялись.
- Общий `bun run check` прошел: форматирование и lint.
- Production build Next.js **16.3.8** прошел, включая проверку типов приложения. Проверка типов пакета Studio также проходила.
- `git diff --check` прошел.
- После исправлений зависимостей `bun audit --audit-level high` не обнаруживает high/critical проблем; сообщены две проблемы ниже выбранного порога. Это результат проверки на момент сессии, а не гарантия для будущих версий.
- В lockfile обновлены Next.js и связанные уязвимые пакеты. В корневом `package.json` закреплены исправления транзитивных зависимостей: `engine.io` 6.6.10, `nanoid` 3.3.18, `tinypool` 2.1.2 и `ws` 8.21.1. Не удалять overrides без повторного аудита.
- Проверены Compose с тестовыми настройками, конфигурация Caddy, shell-синтаксис и backup-образ под UID 1001.
- Через настоящий `restore.sh` восстановлен зашифрованный локальный тестовый снимок: семь аккаунтов, ноль нарушений денежных ограничений, совпадение байтов тестового медиа. Попытки восстановления в занятую БД и непустой каталог отклонены. Проверка внешнего хранилища этим не заменяется.
- Временный контейнер PostgreSQL `ai-studio-production-tests` после тестов остановлен. Его наличие и данные между средами/сессиями не гарантируются.

Для интеграционных тестов требуются отдельная БД с именем, заканчивающимся на `_test`, и одинаковые `DATABASE_URL` и `TEST_DATABASE_URL`. Без `TEST_DATABASE_URL` интеграционные группы пропускаются; обычный `bun test` без него не подтверждает проверки PostgreSQL. Секреты в отчет не включены.

## Что остается до боевого запуска

1. Заполнить реальное окружение, домен и секреты по инструкции `production.md`. Реальные env-файлы автоматически не перезаписывались.
2. Собрать окончательный Docker-образ после всех последних изменений и обновлений зависимостей. Финальная локальная сборка приложения прошла, но полный Docker-образ последней версии не пересобирался.
3. На отдельном стенде проверить браузерный сценарий через HTTPS: вход администратора, создание аккаунта, активацию, выдачу прав и баланса, генерацию и скачивание результата.
4. С рабочим ключом и ограниченным тестовым балансом проверить реальные видео, изображения и TTS, доступность конкретных моделей, тарифы и фактические списания RouterAI.
5. Подключить внешнее резервное хранилище, проверить отправку копии за пределы VPS и восстановление из нее, настроить расписание и уведомления.
6. Подключить внешнее наблюдение readiness, worker, ошибок генерации, расхождений стоимости и резервирования.

Suno, «Видео в аудио», смена голоса и модели без подтвержденной интеграции/тарифа требуют отдельного подключения и приемки. Онлайн-эквайринг не реализован: баланс меняет администратор.

## Состояние рабочего дерева

Изменения не закоммичены. До начала работы в репозитории уже были пользовательские изменения и неотслеживаемые файлы; текущий Git diff содержит и их. Перед созданием коммита проверить весь состав файлов. Не выполнять blanket reset/clean и не удалять чужую работу.

Во время реализации замечалась параллельная запись другим редактором, возвращавшая старый RouterAI-клиент с моками. Финальная версия восстановлена и проверена. При продолжении разработки избегать одновременного изменения одних файлов разными агентами.
