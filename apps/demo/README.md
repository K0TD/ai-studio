# k0td AI Studio — приложение

Next.js-приложение со студией видео, изображений и речи, закрытой регистрацией и административным управлением пользователями. Запуск VPS и резервные копии описаны в [production.md](../../docs/production.md).

## Авторизация и баланс

Администратор синхронизируется из окружения командой `bun run sync-admin` и автоматически перед каждым запуском web-контейнера. Пароль в БД хранится как хеш. Основной администратор защищен от удаления, понижения роли и блокировки через интерфейс. Смена пароля в окружении требует пересоздания web/worker; вне Docker выполните команду синхронизации перед перезапуском процессов.

Пользователей создают в `/admin`, пароль устанавливается по одноразовому приглашению. Баланс, права, задания и файлы принадлежат пользователю в PostgreSQL. Роль VIP сама по себе не открывает модели. Изменения баланса записываются в неизменяемый журнал с причиной и инициатором.

Перед запуском сервер рассчитывает оценку и максимальное списание, резервирует сумму и ставит задание в очередь. Worker обрабатывает задачи вне жизненного цикла HTTP-запроса. Резерв не является отдельным списанием; доступно к расходованию `balanceRub − reservedRub`. Неопределенные исходы провайдера требуют сверки, а не повторного платного запроса.

## Основные маршруты

- `/login`, `/admin/login`, `/admin` — вход и управление.
- `/api/auth/*` — Better Auth; публичная регистрация запрещена сервером.
- `/api/k0td-ai/quote`, `/api/k0td-ai/generate` — расчет и запуск с `Idempotency-Key`.
- `/api/k0td-ai/me`, `/api/k0td-ai/jobs`, `/api/k0td-ai/jobs/[id]`, `/api/k0td-ai/chats` — серверное состояние пользователя.
- `/api/k0td-ai/files`, `/api/k0td-ai/models` — загрузки и проверенный каталог.
- `/api/k0td-ai/admin/*` — административные операции с проверкой роли.
- `/api/health/live`, `/api/health/ready` — liveness/readiness без выдачи секретов.

Псевдонимы `/api/syntx/*` используют те же проверки доступа. Старый `/api/studio/*` отключен, `/studio` перенаправляется в основной клиент. Медиа выдаются только после проверки владельца; video Range поддерживается сервером.

## Команды

```sh
bun run dev             # Разработка
bun run worker          # Фоновый исполнитель, нужен также в разработке
bun run preflight       # Проверка обязательных настроек без печати значений
bun run db:generate     # Создание миграции после изменения схемы
bun run db:migrate      # Применение существующих миграций
bun run sync-admin      # Создание/синхронизация главного администратора
bun run typecheck
bun run build
bun run start
```

Используется `.env.local` из этой папки или окружение процесса. Список настроек: [.env.example](.env.example). Не помещайте ключи в `NEXT_PUBLIC_*`, клиентский Zustand или репозиторий.
